## 移植到 Docusaurus 站点（zh.chinapedia）

把上述 GIF 动画改写成 React + canvas 组件，直接嵌进 `docs/math/哥德巴赫猜想.md`：

- 站点：Docusaurus 3.10.2 / React 19 / MDX（`.md` 也按 MDX 解析，正文里已有 `<figure style={{...}}>`）。
- 做法：文件顶部 `import { useEffect, useRef, useState } from 'react';`；
  动画逻辑用 `export const GB = (() => {...})()` 包成 IIFE（MDX 顶层只稳妥支持 import/export，
  裸 `const` 不放顶层），组件 `export const GoldbachSieve = () => {...}` 定义在**文件末尾**，
  正文里用 `<GoldbachSieve />` 引用——正向后定义是安全的（模块级 const 在渲染前已初始化）。
- 两个坑：
  1. `useState` 初值不能用 `typeof window` 分支，否则 SSR 与客户端首次渲染不一致 → hydration mismatch。
     改成初值恒为 `true`，`prefers-reduced-motion` 的判断挪到挂载后的 `useEffect`。
  2. `<canvas>` 要显式写 `width={GB.W} height={GB.H}`，否则 SSR 阶段默认 300×150，
     `width:100%; height:auto` 会短暂塌成 2:1。
- 验证：`node scripts/build.mjs --slim --out-dir build-mdxcheck` 通过（slim 跳过 9711 篇 wow）。
  另外写了 `scratch/gbcheck.mjs`：从 MDX 里正则抽出 GB 块，`new Function` 求值后用 stub 的
  2D context 跑完 800 帧，确认不抛异常且下标齐全。

### 本站 dev server 的脾气（重要）

- `npm start` 冷启动要 **4 分 15 秒**才编译完 client——wow 的 9711 篇 MDX 全进 webpack，
  而 `npm start` **没有** slim 开关。想快速预览改用
  `node scripts/build.mjs --slim --out-dir <新目录>` + `docusaurus serve`，秒起。
- dev 模式 SSR 只吐 app shell（`<div id="__docusaurus">` 空 div，约 2110 字节），
  内容靠前端 JS 渲染。所以 **curl 抓不到 `<canvas>` 是正常的**，别据此判断页面坏了；
  要看渲染结果得查生产构建产物里的 HTML。
- `docusaurus build/serve --out-dir <已存在的目录>` 会先清空该目录；沙箱有批量删除保护
  （>50 文件要确认），所以每次构建**换一个新目录名**，别复用 build-preview。
- **`docusaurus serve` 的参数是站点目录，不是构建产物目录**——它要在那儿找
  `docusaurus.config.js`，然后服务 config 里的 outDir（默认 `build/`）。
  写 `serve build-check4` 会报 "No config file found in site dir"。
  正确用法：先 `node scripts/build.mjs --slim`（不带 --out-dir，落到默认 `build/`），
  再 `node_modules/@docusaurus/core/bin/docusaurus.mjs serve . --host 0.0.0.0 --port 3000`。
  serve 命中的是真实静态产物（curl 能抓到 `<canvas>`，173KB），比 dev 靠谱。
- 用户的 cmd 窗口里 `npx` 可能不在 PATH（Git Bash 里才有）。用绝对路径的
  node 直呼 `node_modules/@docusaurus/core/bin/docusaurus.mjs` 最稳；
  别依赖 `npx`/全局 CLI。
