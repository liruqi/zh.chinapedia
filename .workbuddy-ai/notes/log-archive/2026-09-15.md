### 本次踩到的新坑（都在 wikitext2md.py 里已修）

1. **`<e>` 清理正则吃掉了正文**。为删一个 stray `<e>` 标签写了
   `</?(?:big|li|e)\b[^>]*>`，结果公式里的 `<e^\gamma` 被当成标签起点，
   一路吞到下一个 `>` —— 整段「is true for all n ≥ 120569# … if *F*<sub>」人间蒸发，
   还导致同行 `$` 不配对、 braces 被误转义。**改成只匹配整块就是标签的**
   `</?(?:big|li)\b[^>]*>` 和 `<[/]?e\s*>`。
2. **行首 `**粗体**` 被当成列表**：列表正则 `^([#*:;]+)\s*(.*)$` 会把 `**Theorem…`
   的 `**` 当标记。改成标记后**必须有空白** `^([#*:;]+)(?:\s+(.*))?$`。
3. **`[[File:…|caption]]` 的 caption 里含 Markdown 链接**：naive 的
   `\[\[([^\[\]|]+)\|([^\[\]]*)\]\]` 匹配不到（caption 里有 `](`）。
   改成**括号深度扫描器** `convert_links()`，在深度 0 处切 `|`，并对 label 递归。
4. **`{{math|{{abs|D}}}}` 双重包裹**产出 `$$|D|$$`（一行 `$$` 会被 remark-math
   当 inline）。通用兜底：收尾时 `re.sub(r"\$\$(?!\n)([^\n$]+)\$\$", r"$\1$")`。
5. **`harvtxt` 与 `harvnb/sfnp` 的括号不同**：`harvtxt` → `Hardy (1914)`；
   `harvnb/sfnp` → ` (Bombieri 2000)`（带前导空格，否则「mathematics.(Bombieri」粘住）。
6. **`[[#章节|文字]]` 自锚点**会生成 `…/wiki/#章节` 这种坏 URL；
   要拼上条目名 → `…/wiki/Riemann_hypothesis#章节`。
7. display 公式还原时要用 `\n\n$$\n…\n$$\n\n` 包一下，否则占位符在行中间时
   `$$` 不在行首。

### 最大的坑：把「只有标题」的 chunk 送给模型 → 整节内容全是编的

- `split_blocks()` 把空行当 verbatim 块，所以「连续文本行」永远被空行切断 →
  每个 chunk 实际就是一个段落；而**标题行自己就是一个 chunk**。
- 后果：模型收到 `## Euler's product formula` 这么一行，就「补全」出一整节——
  27~57 行的虚构内容，还自带编造的 `[^1]: 此处为脚注占位符，原封不动照抄。`
  （把 system prompt 的原文都吐出来了）。29/223 个 chunk 行数对不上，文件从
  1038 行膨胀到 1347 行，脚注定义 67 → 99。
- 修法（都在 md2zh.py）：
  1. 单行为标题 → 走 `HEADING_SYSTEM` 专用提示词，只取一行；
  2. `translate_chunk` 校验 **输出行数必须等于输入行数**，不等就重试，
     最终兜底逐行翻译（`translate_line`）保证 1:1；
  3. 缓存命中也要求行数严格相等（原来只要求 `>=`，所以幻觉被当成有效缓存）；
  4. 收尾再兜一道：任何 `[^n]:` 定义行若不是原文逐字复制，一律丢弃；
  5. 多出来的行里，`[^n]:` 和 `#` 开头的一律判为幻觉丢弃。
- 排查手法（可复用）：按 chunk 比对「输入行数 vs 输出行数」+「输出是否含中日韩字符」。
  行数对不上的 29 个 + 无中文的 6 个 = 35 个重译；行数对得上的 194 个里
  长度比全部 ≤ 1.0，没有幻觉 → 说明**行数就是最有效的幻觉探测器**。

### wiki2md._chat_stream 缺总时限（7.5 小时挂死的元凶）

- `urlopen(timeout=)` 只管单次 recv。服务端只要隔一会儿发个心跳块，每次 recv
  都在超时内成功，连接就能挂几小时（实测挂过 7.5 小时）。
- 已在 `_chat_stream` 里加 `deadline = time.time() + timeout`，读流时超时即抛。
- `md2zh.translate_chunk` 的 timeout 改成随长度走：≤400 字符给 240s，否则 900s；
  且 `n <= 2` 的短段重试一次不成就直接逐行兜底，不再耗满 3×900s。
