## 图片改走 Cloudflare R2（chped 桶）

- 起因：用户指出 `[[File:…]]` 转换出来的 markdown 不对。根因是
  `file_url()` 生成的是 `commons.wikimedia.org/wiki/File:X` —— **文件描述页**（HTML），
  塞进 `<img src>` 必然裂图。thumb.wikimedia.org 又做了反盗链。
- 方案：Commons API 查真实地址 → 下载 → **AWS SigV4 直接 PUT** 到 R2 →
  改写 md 链接为 `https://pub-275e30003c354ac0862cc9839e0f952a.r2.dev/<key>`。
- 产物：`scripts/wikiimg2r2.py`（纯标准库，不装 boto3）+ `scripts/wikiimg-map.json`（缓存映射）。
  凭证在 `scripts/r2.local.json`，已加进 .gitignore，**不提交**；prod 换凭证走
  环境变量 `R2_ENDPOINT/R2_BUCKET/R2_PUBLIC_BASE/R2_ACCESS_KEY/R2_SECRET_KEY`。
- `wikitext2md.py` 的 `file_url()` 顺手改成 `Special:FilePath/<name>?width=1000`，
  这样即使还没跑 R2 那一步，图也是真能显示的。
- 本次共上传 11 张图到 `docs/math/`：黎曼ζ函数 6 张、riemann_hypothesis 5 张
  （riemann_zeta_function 与黎曼ζ函数共用 6 张）。全部 GET 复验字节数一致。
- 提交：zh 1b1a996、en fb6dc52。

### 踩到的坑

- **主机名是 `commons.wikimedia.org`，不是 `commons.wikipedia.org`**。
  第一版正则漏了 wikimedia.org，6 张图一张都没识别出来。
- **SVG / PDF 必须走 thumburl**：`iiurlwidth` 拿到的 thumburl 才是 Wikimedia
  渲染好的 PNG；直接用 `url` 会拿到 .svg / .pdf 源码。反过来 **GIF 要用原图**，
  缩略图会退化成静止的第一帧。
- **系统盘符/网络会随机 RST**（WinError 10054）和 TLS 握手超时。
  所以 `r2_put` 带 4 次重试、`http_head_ok` 带 3 次重试；
  校验阶段出现过「同一 URL 一次 OK 一次 BAD」，是本地网络抖动，不是对象缺失——
  **用 GET 复验字节数，别信单次 HEAD**。
- R2 用**路径风格** `https://<account>.r2.cloudflarestorage.com/<bucket>/<key>`，
  region 填 `auto`，service 填 `s3`；canonical URI 按段编码且**不做路径归一化**
  （S3 与通用 SigV4 不一样）。
- 上传前先对 public URL 做一次 HEAD，已存在就跳过，重跑不会重复传。

## 图注可见化：<figure> + <figcaption>

- R2 那步做完后图能显示了，但 `![图注](url)` 把图注塞进了 **alt 属性**，肉眼看不到，
  只剩一张没说明的图；而且连续几行图片会被合并进同一个段落，并排显示而不是各自成块。
- 新增 `scripts/img2figure.py`：把整行只有一张图的行改写成
  `<figure>` + `![alt](url)` + `<figcaption>图注</figcaption>` + `</figure>`。
  MDX 要求 **JSX 块的子内容要用空行隔开才会被当 markdown 解析**，所以 figure /
  figcaption 内侧都留空行。支持 `--refresh-alt`（按 figcaption 原文重算 alt）。
- alt 用纯文本：`[文字](url)`→文字、`$x$`→可读字符、`[^n]`→删掉。**直接去掉 `$` 会露出
  裸 LaTeX**（`$\zeta$` → `\zeta`），所以加了一张 LaTeX→Unicode 表
  （希腊字母 + ∞ ≤ ≥ ≠ ± × → ∈ 等）以及 `\operatorname{X}`→X、`\mathbb{R}`→ℝ。
- 提交：zh b239507、en 88ed8cf。

### 踩到的坑

- **纯 remark 管线会丢掉裸 HTML**：`scratch/_figcheck.mjs` 第一版用
  remark-parse + remark-rehype 验 `<figure>`，结果 figure=0（remark-rehype 没有
  `allowDangerousHtml`，html 节点被丢掉，只剩里面的 img 段落）。
  **验证 `<figure>` 必须走真正的 MDX 管线**（`@mdx-js/mdx` compile + eval），
  因为只有 MDX 才把这些标签当 JSX 元素。`scratch/_figcheck.mjs` 已改成 MDX 版。
- Python 脚本里写 `\N` 这种 docstring 会触发 `SyntaxError: malformed \N character escape`
  —— 含反斜杠的 docstring 要写成 `r"""…"""`。
- 匹配 `![alt](url)` 时 **alt 里可以有 `]`**（如 `[x,y,z] = [Re(ζ), Im(ζ), t]`），
  别用 `[^\]]*` 取 alt，用 `.*?` 配 `](` 结尾。
- 文件读取后统一 `replace("\r\n", "\n")` 再处理，写盘时再转回 CRLF；
  否则按 `\n` 写的正则（如 FIG_BLOCK_RE）在 CRLF 文件上一个都匹配不到。

## KaTeX 缺 MediaWiki 扩展宏

- 维基原文的 `\C`（复数集）是 **MediaWiki 自己在 MathJax 配置里扩展的宏**，
  KaTeX 完全不认 → 页面渲染成红色 parse error。同批还有 `\R \N \Z \Q \F \sgn`。
- 两处都补：`docusaurus.config.js` 给 rehype-katex 配 `macros` 兜底（以后新导入直接用），
  现存 .md 里用 `scratch/_fixmwext.py` 换成 `\mathbb{C}` 这类标准写法
  （GitHub 的 MathJax 一样不认 `\C`，所以必须换）。
- 全站扫描脚本 `scratch/_macroscan.mjs`：抽 `$…$` / `$$…$$` 逐个 `katex.renderToString`
  试渲染，报未定义宏。**要按 display / inline 分别传 `displayMode`**，
  否则 `\begin{align}` 会被误报成「只能在 display 模式用」。
