## 图片改走 Cloudflare R2（chped 桶）

- 起因：用户指出 `[[File:…]]` 转换出来的 markdown 不对。根因是
  `file_url()` 生成的是 `commons.wikimedia.org/wiki/File:X` —— **文件描述页**（HTML），
  塞进 `<img src>` 必然裂图。thumb.wikimedia.org 又做了反盗链。
- 方案：Commons API 查真实地址 → 下载 → **AWS SigV4 直接 PUT** 到 R2 →
  改写 md 链接为 `https://pub-275e30003c354ac0862cc9839e0f952a.r2.dev/<key>`。
- 产物：`scripts/wikiimg2r2.py`（纯标准库，不装 boto3）+ `scripts/wikiimg-map.json`（缓存映射）。
  凭证在 `scripts/r2.local.json`，已加进 .gitignore，**不提交**；prod 换凭证走
  环境变量 `R2_ENDPOINT/R2_BUCKET/R2_PUBLIC_BASE/R2_ACCESS_KEY/R2_SECRET_KEY`。
- `wikitext2md.py` 的 `file_url()` 顺手改成 `Special:FilePath/<name>?width=1000`，
  这样即使还没跑 R2 那一步，图也是真能显示的。
- 本次共上传 11 张图到 `docs/math/`：黎曼ζ函数 6 张、riemann_hypothesis 5 张
  （riemann_zeta_function 与黎曼ζ函数共用 6 张）。全部 GET 复验字节数一致。
- 提交：zh 1b1a996、en fb6dc52。

### 踩到的坑

- **主机名是 `commons.wikimedia.org`，不是 `commons.wikipedia.org`**。
  第一版正则漏了 wikimedia.org，6 张图一张都没识别出来。
- **SVG / PDF 必须走 thumburl**：`iiurlwidth` 拿到的 thumburl 才是 Wikimedia
  渲染好的 PNG；直接用 `url` 会拿到 .svg / .pdf 源码。反过来 **GIF 要用原图**，
  缩略图会退化成静止的第一帧。
- **系统盘符/网络会随机 RST**（WinError 10054）和 TLS 握手超时。
  所以 `r2_put` 带 4 次重试、`http_head_ok` 带 3 次重试；
  校验阶段出现过「同一 URL 一次 OK 一次 BAD」，是本地网络抖动，不是对象缺失——
  **用 GET 复验字节数，别信单次 HEAD**。
- R2 用**路径风格** `https://<account>.r2.cloudflarestorage.com/<bucket>/<key>`，
  region 填 `auto`，service 填 `s3`；canonical URI 按段编码且**不做路径归一化**
  （S3 与通用 SigV4 不一样）。
- 上传前先对 public URL 做一次 HEAD，已存在就跳过，重跑不会重复传。
