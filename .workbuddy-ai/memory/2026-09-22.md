## 新增 scripts/prebuild_check.mjs：把踩过的坑固化成发布前预检

起因：这一轮连续遇到「MDX 编译能过、局部校验也全绿，但真构建 / 真访问才炸」的问题，
每次都是靠人肉排查。于是把五类已知故障写成一个扫描脚本，退出码 1 = 有问题，可直接接 CI。

- 用法：`npm run check`（默认扫 `docs/`，跳过 `wow/`）；
  `node scripts/prebuild_check.mjs docs/math` 只扫某个目录；`--wow` 连 9711 篇一起扫。
- 检查项：
  1. 标题里的裸 `<` `>`（TOC 会把 TeX 源码原样插进 HTML → html-minifier-terser
     Parse Error → **整站构建失败**；`\lt` / `\gt` / `\le` / `\ge` 不算）
  2. MDX 里的裸 `{expr}`：compile() 不报错，运行时 ReferenceError 白屏
     —— 所以脚本是**编译 + eval** 两步，`eval` 才抓得住
  3. KaTeX 未定义宏（`\C \R \N \Z \Q \F \sgn \arccot \arcsec \arccsc`）
     —— 必须和 `docusaurus.config.js` 里的 `katexMacros` 保持一致
  4. 图还在裸链维基（必须全部在 `pub-275e…r2.dev`）
  5. 脚注定义了没被引用 / 引用了没定义
  6. 裸 URL `[https://…]`（后面没跟 `(` 的才算）

### 脚本自己踩的两个坑

- **脚注引用误判**：原来用 `(?!:)` 区分「定义」和「引用」，但中文里写
  「代码库展示了高质量的工程实践[^23]：」时，引用后面紧跟冒号，被当成定义 → 误报。
  正确做法：**先把「定义行 + 缩进续行」整段抠掉**，剩下的 `[^n]` 才算引用。
- **裸 URL 误判**：`[https://host](url)` 是合法的链接/脚注定义，不能算裸 URL。
  正则要加负向前瞻 `(?!\()`。孪生素数.md 一开始报了 27 条，全是误报。

## 新增 scripts/wikiterm.py：英文词条 → 中文正式译名

`en.wikipedia.org` 的 `prop=langlinks&lllang=zh` 拿中文维基条目名，
这就是权威译名。三级兜底，质量依次递减：

1. **langlinks** —— 中文维基条目名，可靠。`Riemann xi function → 黎曼ξ函数`、
   `Mellin transform → 梅林变换`、`Theta function → Θ函数`、`Siegel zero → 西格尔零点`
2. **Wikidata 中文标签/别名** —— 条目没中文版时的兜底，**质量明显差一档**，
   不少是机翻/生造：`Andrew Granville → 安德鲁·关维`、`János Pintz → 平茨·亚诺什`
3. 都没有 → None

用法：`python scripts/wikiterm.py "Riemann xi function"`、
`--scan docs/math/`（抽 .md 里所有 en.wikipedia.org 链接）、`--glossary`、`--json`、
`--no-wikidata`（严格模式）、`--fix-cache`（整理缓存）。
结果缓存在 `scripts/wiki-zh-terms.json`（提交，378 条）。

### 踩的坑

- **简繁转换必须分批**。langlinks 给的是源标题，可能是繁体（黎曼ξ函數、Θ函數）。
  用 `zh.wikipedia.org` 的 `action=parse&variant=zh-cn` 转。
  `converttitles` 靠不住（没有需要转换的词时干脆不返回 converted）。
  原来一次塞 378 行，parse 返回行数一对不上就**整批退回原文**，繁体一个没转掉 →
  改成 40 条一批，坏掉的只有那一小批。
- **维基 API 会 429**：472 个词条的批量查询直接被限流回来。
  `api()` 加限速（两次请求至少隔 1.2s）+ 429 按 `Retry-After` 退避。
- **本机网络同时跑构建时必 RST**（WinError 10054）。后台补查 76 个词条时
  31 分钟只成功 5 个，其余全是连接被重置 —— **别在 `npm run build` 期间查维基 API**。
- **键要按小写去重**：维基标题大小写等价，`Riemann Xi function` 和
  `Riemann xi function` 是同一条目，扫描会当成两个词（去重掉 19 条）。
  变体里留「句子式大小写」那个（小写字母最多的）。

## 结案：标题裸尖括号到底谁会炸（用真实 TOC 管线实测）

写 `scratch/_tocangle.mjs`，直接调 `@docusaurus/mdx-loader/lib/remark/toc/utils.js`
的 `toHeadingHTMLValue()`（remark-parse + remark-math 解析后），实测四种标题：

| 标题 | TOC 输出 | 是否漏裸 `<` |
|---|---|---|
| `## "No Siegel zeros" for *D* \< 0` | `&quot;…&quot; for <em>D</em> &lt; 0` | 否 ✅ |
| `## 裸尖括号 D < 0`（普通文本） | `裸尖括号 D &lt; 0` | 否 ✅ |
| `## 公式 $D < 0$` | `公式 D < 0` | **是 ⚠** |
| `## 已转义 \< 与 \>` | `已转义 &lt; 与 &gt;` | 否 ✅ |

结论（推翻了之前的猜测）：

- **普通文本里的裸 `<` 是安全的**——remark 解析成 text 节点，`escapeHtml()` 转成 `&lt;`。
- **`\<` 也是安全的**——Markdown 转义后同样是 text 节点 → `&lt;`。
  所以 `prebuild_check.mjs` 报 `en.chinapedia/docs/math/siegel_zero.md` 的
  `## "No Siegel zeros" for *D* \< 0` 是**假阳性**，且这行本来就是 2e1216b 那次修的产物。
- **真正会炸的是「标题里的数学公式含裸 `<`」**：`toHeadingHTMLValue()` 的 switch
  只显式处理 `text / heading / inlineCode / emphasis / …`，`inlineMath` 落到
  `default: return toString(node)`，mdast-util-to-string 原样返回 `D < 0`（连 `$` 都剥掉），
  **不转义** → 裸 `<` 进 TOC 的 `dangerouslySetInnerHTML` → html-minifier-terser
  Parse Error → 整站构建失败。

改法：`prebuild_check.mjs` 的 probe 里加 `.replace(/\[<>]/g, '')` 放行 `\<` `\>`，
**但裸 `<>` 继续报**（正好覆盖公式那一种）。已加注释说明。
回归自测：合成文件里 `## 安全转义 \< 0` 不报、`## 危险公式 $D < 0$` 照报，退出码 1。

**校验脚本用法坑**：`node scripts/prebuild_check.mjs <路径>` 的 `<路径>` 必须是
**目录**，传文件路径会因为 `readdirSync` 抛 ENOTDIR 而静默扫到 0 个文件
（输出「预检文件数: 0 / √ 全部通过」，看着像通过，其实是啥也没扫）。

## 全站构建 OOM（用户在 Mac 上跑出来）

崩溃栈：`v8::FatalProcessOutOfMemory` → `Runtime_MapGrow` / `Builtins_MapPrototypeSet`
→ `zsh: abort`。特征是「Map 一直 grow」，不是文件句柄泄漏（区别于之前的 EMFILE）。

**根因：docs/wow 是 9711 篇，占全站 9729 篇的 99.8%**（`docs/wow/capycraft` 是
submodule）。每篇都要进 webpack 模块图，堆撑爆。用户那次跑的是裸 `npm run build`，
没有加 `--max-old-space-size`，用的是默认堆。

两条对策，都已加进仓库：

1. `npm run build:big` = `NODE_OPTIONS=--max-old-space-size=8192 docusaurus build`
   （原来只能在命令行手打这个前缀）。内存小的机器调小数字，别超过物理内存否则换页更慢。
2. `npm run build:slim` = `SKIP_WOW=1 docusaurus build` —— `docusaurus.config.js`
   读到这个变量就把 `wow/**` 加进 docs 插件的 `exclude`，并**改输出到 `build-slim/`**
   （防止误把瘦身版发布出去）。改正文/样式时用这个，一两分钟出结果。
   - `exclude` 会覆盖插件默认值，所以写成 `['wow/**', ...DEFAULT_EXCLUDE]` 保留默认四条。
   - 顶层本来就有 `onBrokenLinks: 'log'`，**不要再在 docs 插件里设 'throw'**，
     否则就把既有的 log 行为改成中断构建了。
   - Windows 的 cmd 不支持 `SKIP_WOW=1 cmd` 前缀，要用 Git Bash 或 `set SKIP_WOW=1&&`。

验证：改完 `node --check`（复制成 .mjs）通过；`package.json` 仍是合法 JSON。
