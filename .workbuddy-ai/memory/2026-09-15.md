## wiki2md.py：KaTeX 改为默认 + GitHub 渲染兼容

- **GitHub 行内公式的坑（实测确认）**：起始 `$` 前面必须是**空白或行首**，紧跟中文标点
  （`，。、：（）`等）时 GitHub 不渲染，会原样显示源码。结尾 `$` 后面接中文标点则没问题
  （`$(6n-1,6n+1)$（` 能正常渲染）。所以只需在起始 `$` 前补空格。
  - 反面案例（用户报的）：`…（$n > 1$ 为自然数）…，$n$ 的…` 后两个都不渲染。
  - 全库扫描出 16 处，行号 61/97/105/119/123。
- **GitHub 第二个坑**：正文里非分隔符的裸 `$` 也必须处理（官方文档明确要求）。
  HathiTrust 的 URL `?id=uc1.$b416748` 里有裸 `$`，第 5 行同时有行内公式 → 会打乱配对。
  解法：把 URL 里的 `$` 百分号编码成 `%24`（等价 URL，且链接文字不受影响）。
- 不要用 `$`…`$` 这种 GitHub 专用写法，remark-math 不认，会让站点渲染失败。
- 新增后处理函数（katex 模式下自动跑，顺序：escape_dollar_in_urls → fix_github_math）：

- RULE6_KATEX 同步加了 (a)~(e) 条：三行 `$$`、起始 `$` 前留白、LaTeX 命令、URL 里 `$`→`%24`、

## 黎曼猜想页线上崩溃 `li is not defined`（修复）

- 现象：https://zh.chinapedia.org/wiki/math/黎曼猜想 打开即白屏，控制台 `ReferenceError: li is not defined`。
- 根因：参考文献第 867 行残留未包进 `$…$` 的 LaTeX
  `\pi(x)-\operatorname{li} x`。MDX v3 把正文里的 `{li}` 当 **JS 表达式**求值 →
  运行时 ReferenceError。**`compile()` 不会报错**（产物里就是一个裸标识符 `li`），
  所以之前的「MDX COMPILE OK」是假阳性。
- 修复：
  1. `docs/math/黎曼猜想.md`
     - 867 行改成 `*On sign-changes of the difference* $\pi(x)-\operatorname{li} x$`
     - 761 行 `\zeta(1)=\log\infty`、`\log\log\infty` 补 `$…$`
     - 542 行 `$|S(T)|$ < 1` → `$|S(T)| < 1$`（`<` 也收进公式）
  2. `scripts/wiki2md.py` 新增 `escape_mdx_braces()` + `_escape_mdx_text()`，
     在 `main()` 里（KaTeX 处理之后）统一把**数学环境与行内代码之外**的 `{}` 转义成
     `\{ \}`，并把后面不跟 `[A-Za-z/!?]` 的裸 `<` 转义成 `\<`（`<blockquote>`、
     `<br />`、`<!-- -->`、`<url>` 均不动）。
- 新增校验工具 `C://Users//liruqi//.workbuddy-ai//binaries//node//workspace//r_mdxrun.mjs`：
  **实际执行**编译产物（stub jsx，无需装 react）来捕捉未定义标识符。
  已用反例验证：含 `{li}` 的样本报 `ReferenceError: li is not defined`；
  `git show HEAD:docs/math/黎曼猜想.md`（修复前）同样报错，修复后 RUNTIME OK。
  ⚠️ 坑：编译产物以 `return {default: MDXContent}` 结尾，末尾再拼 `return MDXContent`
  是不可达的，必须取 `mod(runtime).default` 再调用。
- 全站扫描（docs/ 下 9727 个 .md）：数学环境外的 `{}` / 裸 `<` / 裸 LaTeX —— **0 个问题文件**。
